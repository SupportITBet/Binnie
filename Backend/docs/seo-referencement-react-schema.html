02

Pourquoi le rendu 100% client pose un vrai problème

Tous les robots qui visitent le site ne se comportent pas de la même façon face à une page vide qui se remplit en JavaScript.

✅ Google (Googlebot)
Exécute le JavaScript avant d'indexer — voit le contenu et les balises <SEO />, mais avec un délai (passage en deux temps) et un budget de rendu limité par page.
❌ Facebook / WhatsApp / Messenger
Le crawler facebookexternalhit ne exécute pas le JavaScript — il lit uniquement le HTML brut. Résultat : aperçu de partage avec le titre/description génériques de index.html, jamais ceux posés par <SEO />.
❌ LinkedIn / Twitter (X)
Même comportement — pas d'exécution JS. Un lien du site partagé sur LinkedIn affichera "React App" comme titre tant que le problème n'est pas corrigé.
🟡 Bing
Support JS partiel et moins fiable que Google — comportement intermédiaire, à ne pas présumer favorable.
Constat concret : aujourd'hui, un lien BET partagé sur Facebook, WhatsApp ou LinkedIn affiche très probablement "React App" comme titre d'aperçu — quelle que soit la page partagée. Ça affaiblit directement l'efficacité du tracking réseaux sociaux (GA4 ou maison) : un aperçu cassé réduit le taux de clic avant même que le visiteur arrive sur le site.
