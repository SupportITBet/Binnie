2 · Découverte en creusant le workflow réel : qui assigne le coach en coaching privé ?

Avant de concevoir l'import du coaching privé, on a tracé le parcours réel d'un dossier privé dans le code — la réponse dépend du lieu, ce qui n'était pas évident au départ.

1
Création + transmission
L'assistante crée le dossier (niveau, formation, lieu, coût, disponibilités) et le transmet au PA
Bouton explicite "Transmettre au PA" (actif seulement si le dossier est complet) → dossier_statut:"en_attente_validation".
2
Validation + paiement
Le PA valide le dossier, l'assistante active le paiement
dossier_statut passe à "paiement_en_attente" puis "paiement_recu" — ou "invalide" avec motif si problème.
3
Bifurcation selon le lieu — le point clé
Après paiement, le dossier ne part pas toujours au même endroit
routing_statut devient "onboarding_en_attente" si le lieu est "en_ligne", ou "assistante_a_traiter" si le lieu est "cabinet" (présentiel) ou "domicile" — deux destinations différentes selon un seul champ.
4
Qui assigne le coach — la nuance à retenir
Présentiel/domicile → l'assistante assigne elle-même. En ligne → c'est le PA.
Pour le présentiel/domicile, le dossier revient chez l'assistante avec une bannière "À finaliser" — elle crée la classe (capacite_max:1, le marqueur universel du coaching privé) et choisit le coach elle-même. Pour l'en ligne, le dossier suit le circuit onboarding puis atterrit chez le PA, qui assigne le coach comme pour une classe de groupe.
⚠ La règle "c'est toujours le PA" énoncée plus tôt était incomplète
🏢 Présentiel / domicile
  • Retour chez l'assistante après paiement (routing_statut:"assistante_a_traiter")
  • L'assistante crée la classe ET choisit le coach elle-même
  • Le PA est notifié une fois la finalisation faite (routing_statut:"centre_assigne")
🌐 En ligne
  • Part chez Onboarding après paiement (routing_statut:"onboarding_en_attente")
  • Puis atterrit chez le PA, qui assigne le coach
  • L'assistante n'intervient plus après la transmission initiale

Ce que fait l'import, par ligne

1. Résolution coach→par email — bloquant si introuvable (seule contrainte dure de cet import).
2. POST /api/groupes→crée la classe privée (capacite_max:1, type de cours selon le lieu, coach déjà assigné) — même endpoint que l'import classes de groupe.
3. POST /api/groupes/:id/apprenants→ajoute l'apprenant à cette classe — crée aussi automatiquement son compte, exactement comme pour l'import apprenants prévu en section 4.
4. Dossier assignations_parcours→créé directement avec les statuts finaux (routing_statut:"centre_assigne", statut:"converti") plutôt que les statuts intermédiaires du circuit normal — pour remonter dans l'historique "Prospects parcours" et les KPIs commerciaux, sans repasser par une fausse validation.

Assistante en ligne — ajoutée aux deux imports Onboarding (classes ET coaching privé)

Découverte en creusant le vrai parcours site web → assistante : pour du en ligne, une assistante intervient dès le début (le visiteur la choisit lui-même sur le site), que ce soit pour du groupe ou du privé — une migration en masse doit refléter ça dès la création, pas l'ignorer.

Résolution→colonne "Assistante (email)*" — obligatoire, résolue via GET /api/parcours/assistantes filtrées type_cours==="en_ligne", ligne rejetée si introuvable — même traitement que le Coach.
Coaching privé→l'assistante devient assistante_id, un vrai champ FK sur le dossier — effet de bord bienvenu : le serveur en déduit automatiquement onboarding_id via assistantes.onboarding_id (parcours.js:445), donc l'attribution "Assistante Onboarding" devient correcte sans bricolage.
Classes de groupe→groupes n'a pas de champ assistante — created_by (la vraie clé) reste forcé au compte qui importe côté serveur (groupes.js:2193, jamais accepté du client). Seul created_by_nom est modifiable après coup (PATCH) : c'est là qu'est tracé le nom de l'assistante, en toutes lettres — traçabilité oui, lien technique (FK) non, contrainte du backend actuel.

Corrections trouvées en testant pour de vrai

Ce qui manquaitCause réelleCorrection
Ligne sans nom ni coach reconnu disparaissait de l'aperçu sans trace Le filtre final ne gardait que les lignes avec un nom ou un coach résolu — une ligne avec le mauvais gabarit de fichier (ex: import classes utilisé à la place du gabarit privé) perdait les deux et disparaissait silencieusement. Une ligne n'est ignorée que si la ligne Excel est entièrement vide — sinon elle reste visible, même invalide, avec ses erreurs affichées.
Classe "prive" (100% en ligne) affichait "—" au lieu de "En ligne" dans la liste des groupes Trou pré-existant dans l'affichage (pas propre à l'import) — la colonne Type ne reconnaissait que en_ligne/domicile/centre, jamais prive. Ajout de prive comme alias de "En ligne" à 2 endroits (liste des groupes + détail du groupe).
"Programme" et "Début supposé" vides dans le dossier apprenant Ces deux champs se lisent depuis un JSON séparé (groupes_apprenants.note), pas depuis les colonnes du dossier — l'import ne remplissait que assignation_id dans ce JSON. Ajout de programme et date_debut dans ce même JSON, dans les deux imports (Commercial + Onboarding).
"Offre souscrite" et "Statut paiement" pas à jour inscription_offre jamais envoyé côté Onboarding ; statut_paiement jamais envoyé nulle part — reste à sa valeur par défaut "en attente", fausse pour une relation déjà réelle et déjà payée. inscription_offre ajouté ; statut_paiement passé à "confirmé" automatiquement si un montant payé est renseigné dans le fichier.
Le SuperAdmin n'était jamais notifié des classes/apprenants/dossiers créés par l'import POST /api/groupes et POST /api/groupes/:id/apprenants ne notifiaient que l'e-learning et le PA Advisor ; POST /api/parcours/assignation ne notifiait personne à la création — comportement déjà là avant l'import, pas introduit par lui, mais insuffisant pour garder une visibilité totale sur des imports en masse. Notification SuperAdmin ajoutée aux 3 endpoints — s'applique aussi bien à une création manuelle qu'à un import, cohérent avec la demande de visibilité totale.
✓ SuperAdmin notifié désormais sur toute création de classe, tout ajout d'apprenant et toute création de dossier — manuelle ou via import, sur les 3 endpoints réutilisés par les imports.

4 · Import apprenants — livré (Commercial présentiel)

Le bouton "📤 Importer" vit dans l'onglet Assignation (celui des dossiers), pas dans un nouvel onglet. Nouveauté par rapport aux imports classes/coaching privé : le fichier peut mélanger des lignes avec une classe déjà précisée (colonne optionnelle) et des lignes sans — celles-ci sont assignées en un seul geste groupé après l'import, plutôt que ligne par ligne.

✅ Ligne avec "Classe" renseignée
  • Résolution par nom exact (insensible à la casse) parmi les classes présentiel/domicile du centre de l'assistante
  • Introuvable → erreur bloquante sur la ligne (pas d'assignation silencieuse à la mauvaise classe)
  • Classe clôturée/terminée référencée → erreur bloquante également
  • Dossier + inscription faits en un seul passage, comme les imports classes/coaching privé existants
🕓 Ligne sans "Classe"
  • N'est jamais une erreur — badge neutre "à assigner après import" dans l'aperçu
  • Seul le dossier (assignation) est créé pendant l'import
  • Un seul modal, après le rapport de création, pour choisir la classe cible de tout le lot
  • Si toutes les lignes ont une classe renseignée, ce modal n'apparaît simplement pas
ℹ️ Dépassement de capacité (nb_apprenants ≥ capacite_max) : avertissement seulement, jamais bloquant — ce sont des inscriptions déjà réelles, le chiffre de capacité affiché peut être indicatif. Le profil enfant (parent + enfant) reste prévu pour cette phase, avec les mêmes règles que le reste de la plateforme (email/téléphone de l'apprenant vides pour forcer un identifiant technique propre à l'enfant, jamais ceux du parent).

Nouveau garde-fou — vérification anticipée des classes, avant le détail ligne par ligne

Sur un fichier de 800 lignes, une classe mal orthographiée dans la colonne "Classe" peut toucher des centaines de lignes d'un coup sans que ça saute aux yeux dans un tableau détaillé aussi long. Le premier bloc de l'aperçu regroupe donc les classes par nom distinct, avant même le détail ligne par ligne — l'assistante voit immédiatement si quelque chose cloche, corrige le fichier (ou la classe visée) et relance, au lieu de valider un import et de découvrir le problème après coup.

✓ Livré : les lignes avec une classe introuvable restent bloquantes (exclues de l'import, comme les 2 autres imports), mais corrigeables directement dans le tableau — la colonne "Classe" de l'aperçu ligne par ligne est un champ éditable : on tape le bon nom, la résolution se refait instantanément contre les classes réelles, sans réuploader le fichier. Ce résumé ne remplace pas le détail ligne par ligne — il vient juste avant, comme un raccourci pour repérer un problème massif en un coup d'œil plutôt qu'en scrollant 800 lignes.
