Schéma de déploiement

Un repo, une machine, quatre adresses

Les trois frontends et le Backend tournent tous sur le même VPS Hostinger. Nginx joue l'aiguillage : il sert les trois builds React en fichiers statiques et fait reverse-proxy vers l'API Node pour tout ce qui commence par api.

Dépôt GitHub
Builds statiques (3 frontends)
VPS — Nginx + PM2

Marche à suivre

01

Domaine & VPS

Les deux achats de départ, chez Hostinger.

  1. Acheter le nom de domaine

    Dans la boutique de domaines Hostinger. Aucune configuration DNS à faire tout de suite — l'étape 04 donne la table finale.

  2. Commander le VPS

    Un plan VPS classique (2 vCPU / 4 Go de RAM suffit pour l'API + les 3 sites statiques). Note l'adresse IP fournie — elle est utilisée sur les quatre enregistrements DNS.

02

Préparer le VPS

Node, PM2 pour le Backend, un build par frontend.

  1. Installer Node, Git, Nginx et cloner le repo

    ssh root@<IP_DU_VPS>
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo bash -
sudo apt install -y nodejs git nginx
cd /var/www && git clone https://github.com/DOUMBISSS/Binnie.git
cd Binnie

  2. Backend — lancer l'API avec PM2

    cd Backend && npm install
sudo npm install -g pm2
pm2 start src/server.js --name bet-backend
pm2 save && pm2 startup

  3. Les 3 frontends — build statique

    Chaque app produit un dossier build/ que Nginx servira directement — pas de process Node pour eux.

    cd ../Frontend && npm install && npm run build
cd ../dash && npm install && npm run build
cd ../bet-elearning && npm install && npm run build
03

Nginx — 4 blocs serveur

Un fichier par sous-domaine dans /etc/nginx/sites-available/, puis SSL en une seule commande.

  1. Bloc statique — exemple pour le Frontend

    server {
    listen 80;
    server_name tondomaine.com;
    root /var/www/Binnie/Frontend/build;
    index index.html;
    location / { try_files $uri /index.html; }
}

    Même schéma pour dash.tondomaine.com → dash/build et elearning.tondomaine.com → bet-elearning/build.

  2. Bloc proxy — l'API

    server {
    listen 80;
    server_name api.tondomaine.com;
    location / {
        proxy_pass http://localhost:5001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

  3. Activer les 4 blocs + SSL

    sudo ln -s /etc/nginx/sites-available/* /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d tondomaine.com -d dash.tondomaine.com -d elearning.tondomaine.com -d api.tondomaine.com

05

Chaque mise à jour, ensuite

Un seul script à déclencher après un push.

  1. deploy.sh — sur le VPS

    cd /var/www/Binnie && git pull

cd Frontend && npm install && npm run build && cd ..
cd dash && npm install && npm run build && cd ..
cd bet-elearning && npm install && npm run build && cd ..

cd Backend && npm install && pm2 restart bet-backend

    Nginx n'a besoin d'aucun redémarrage — il sert toujours le contenu à jour du dossier build/ dès qu'il est réécrit.

  2. Déclenchement automatique

    Un webhook GitHub (ou une tâche cron légère) qui appelle ce script à chaque push sur master, pour ne plus avoir à se reconnecter en SSH manuellement.

Domaine et IP affichés ici sont des emplacements à remplacer par les valeurs réelles une fois le domaine choisi et le VPS provisionné.
