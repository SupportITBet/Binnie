BET · Audit — Parcours apprenant

Transfert d'un apprenant vers un autre groupe — état des lieux

Ce que fait réellement le bouton "Transférer" aujourd'hui, où il vit dans le code, et ce qui manque encore avant de le considérer complet.

✅
La fonctionnalité existe et est réelle — pas un mock. Mais elle vit entièrement dans dash (le système historique "groupes" du cœur de métier BET), pas dans bet-elearning. Côté e-learning (classes_elearning_apprenants), aucun équivalent n'existe : transférer un apprenant d'une classe e-learning à une autre n'est pour l'instant possible nulle part.
1
Déclenchement
L'onboarding ou le coach initie le transfert
Deux points d'entrée réels, tous deux branchés sur la même route backend : le modal complet côté Onboarding (recherche du groupe cible par niveau, motif, préférences de créneau) et une version "signaler un transfert" côté coach.
🎓 Onboarding — OnboardingDashboard.jsx 👤 Coach — EspaceProfesseur.jsx ⚙️ POST /api/groupes/transfert
2
Ancien groupe
La ligne existante est fermée proprement, pas supprimée
La ligne groupes_apprenants d'origine passe au statut "transfere" avec une date de retrait — un soft-close. L'historique (présences, évaluations) reste rattaché à cette ligne et à l'ancien groupe, donc rien ne se casse rétroactivement.
⚙️ groupes_apprenants.statut → "transfere" + date_retrait
3
Nouveau groupe
Une ligne fraîche est créée dans le groupe cible
Nom, email, téléphone, niveau et le champ JSONB note (suivi/progression) sont recopiés sur la nouvelle ligne, créée avec le statut "periode_test". Les compteurs nb_apprenants des deux groupes sont mis à jour.
⚙️ INSERT groupes_apprenants (statut: periode_test) ⚙️ nb_apprenants recalculé sur les deux groupes
4
Notifications
Trois destinataires possibles, selon qui a initié le transfert
Le nouveau coach est toujours notifié. Selon que l'initiateur est le coach ou l'onboarding, l'assistante commerciale et/ou l'assistant onboarding (added_by) reçoivent aussi un message dédié.
🔁 Nouveau coach — toujours notifié 🧭 Assistante commerciale — si initié par un coach 🎓 Assistant onboarding — selon added_by

Ce qui est couvert, ce qui ne l'est pas

✓
Écriture réelle en base
Pas de mock ni de localStorage — vrais UPDATE/INSERT Supabase sur groupes_apprenants.
✓
Confirmation avant action
Modal avec sélection explicite du groupe cible, motif, bouton désactivé tant que rien n'est choisi.
✓
Historique préservé
Présences et évaluations restent attachées à l'ancienne ligne — rupture propre, rien ne se réécrit après coup.
✓
Suivi pédagogique transféré
Le champ JSONB de suivi/notes/progression est recopié sur la nouvelle ligne — ne repart pas de zéro.
✓
Rosters propres
Listes actives (front et back) filtrent sur statut IN (actif, periode_test) — l'ancienne ligne "transfere" ne pollue rien.
✓
Notifications multi-parties
Nouveau coach, commercial et/ou onboarding — pas un message générique unique.
✗
Aucune vérification de capacité
capacite_max existe sur groupes mais n'est jamais comparé à l'effectif avant d'ajouter quelqu'un — un groupe complet peut recevoir un transfert.
✗
Aucun garde-fou contre le doublon
Rien n'empêche de transférer deux fois le même apprenant, ni de le transférer vers un groupe où il a déjà une ligne active.
✗
Pas de trace d'audit
logAudit est utilisé ailleurs dans ce même fichier backend mais jamais appelé dans la route de transfert — aucune entrée dans audit_logs.
✗
Aucun équivalent côté bet-elearning
Rien dans classes_elearning_apprenants — transférer un apprenant e-learning d'une classe à une autre n'est possible nulle part.

Deux mondes de données distincts, à ne pas confondre

✓ dash — cœur de métier BET
  • Modèle groupes / groupes_apprenants — le système historique, non lié à l'e-learning.
  • Transfert réel et fonctionnel, accessible depuis deux écrans (Onboarding et Espace Professeur).
  • Présences et évaluations propres à ce modèle (groupes_presences, evaluations_groupes).
✗ bet-elearning — portail e-learning
  • Modèle classes_elearning / classes_elearning_apprenants — entièrement séparé, aucun pont entre les deux.
  • Aucune route, aucun bouton, aucun modal de transfert d'apprenant entre classes e-learning.
  • Si le besoin existe côté e-learning, c'est à construire de zéro — pas une extension du système dash existant.

Ce qui circule, techniquement (dash)

groupes_apprenants→ligne d'origine fermée (statut "transfere" + date_retrait), nouvelle ligne créée dans le groupe cible (statut "periode_test")
groupes.nb_apprenants→recalculé sur l'ancien ET le nouveau groupe après le transfert
note (JSONB)→suivi pédagogique / progression — copié tel quel sur la nouvelle ligne, seul élément de contenu qui traverse le transfert
groupes_presences→reste rattaché à l'ancien ga_id / groupe — historique non réécrit, nouvelle présence s'attachera au nouveau ga_id
evaluations_groupes→même logique — attaché à l'ancien ga_id, rien ne migre ni ne se duplique
notifications→nouveau coach systématiquement, + assistante commerciale et/ou onboarding selon qui a initié le transfert
