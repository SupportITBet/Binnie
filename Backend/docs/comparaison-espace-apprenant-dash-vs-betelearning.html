Espace Apprenant (dash) vs Dashboard Apprenant (bet-elearning)

Deux implémentations indépendantes du même rôle (l'apprenant), sur deux modèles métier distincts : dash = coaching individuel/groupe (groupes_apprenants, assignations_parcours), bet-elearning = classes e-learning B2B (classes_elearning_apprenants). Aucune fusion prévue — ce document sert uniquement à vérifier les écarts d'onglets, de données et de mocks restants.

dash/src/Pages/EspaceApprenant/EspaceApprenant.jsx — ~4913 lignes bet-elearning/src/pages/apprenant/DashboardApprenant.jsx — ~4450 lignes 4 zones encore mockées côté dash
🔎 Les deux dashboards ne se recouvrent que partiellement : dash a des onglets propres au coaching (Planning, Examens, Boutique, Paiement, Témoignage), bet-elearning a des onglets propres au e-learning gamifié (Mini-jeux, Badges, Dictionnaire, Classement, Exercices & devoirs). Sur les onglets communs, les sources de données divergent presque toujours (endpoint Express côté dash, requête Supabase directe côté bet-elearning). Point le plus actionnable : MES_OBJECTIFS est encore un tableau 100% mocké dans l'onglet Objectifs de dash — rien n'est lu depuis le backend.

Architecture & authentification

🟢 dash
  • Auth JWT custom, token dans localStorage.user_token.
  • Données via endpoint Express dédié : GET /api/apprenants/mon-espace — un seul appel serveur qui agrège tout.
  • Pas de nav partagée : header/tabs codés directement dans le fichier (comme CommercialDashboard.jsx).
  • Style : tout en inline styles, palette codée en dur localement.
  • Fichier monolithique unique, aucun découpage en sous-composants pour les onglets.
🟣 bet-elearning
  • Auth Supabase (supabase.auth.signInWithPassword()), session via useAuth() / AuthContext.jsx, token bet_access_token.
  • Données majoritairement via requêtes Supabase directes côté frontend (appels aux lignes 890, 913, 917, 923, 935, 944, 953, 962) — pas d'endpoint d'agrégation unique.
  • Nav partagée : TopNavLayout.jsx, réutilisé aussi par les dashboards prof/admin/parent.
  • Style : également inline styles, mais avec support thème (ThemeContext).
  • Même pattern monolithique (fichier unique ~4450 lignes, pas de sous-composants par section).
Aucune passerelle entre les deux modèles d'auth — attendu et voulu, dash et bet-elearning restent deux produits indépendants.

Données encore mockées côté dash — à vérifier / corriger

C'est la partie la plus actionnable de cette comparaison : ce qui reste en dur dans EspaceApprenant.jsx alors que bet-elearning a déjà l'équivalent branché sur de vraies données.

✕
MES_OBJECTIFS — tableau 100% mocké (lignes 159-163, rendu 3143-3154)
L'onglet Objectifs affiche un tableau fixe défini en dur dans le composant, jamais remplacé par un fetch. Aucun endpoint /api/apprenants/.../objectifs n'existe côté Backend pour l'instant.
✕
ONBOARDING_VIDEOS — mock (lignes 80-84)
Les vidéos d'accueil affichées dans l'onglet Onboarding (1910) sont une liste statique, non liée à une table ou un CMS. bet-elearning gère sa section onboarding (1180) avec un contenu réellement piloté.
✕
CONTACTS_ADMIN — mock (lignes 86-91)
Le menu déroulant de la modal "Contacter un admin" (onglet Contacts, 3196) liste des contacts fixes plutôt que des comptes admin réels issus de utilisateurs.
✕
MON_PROFIL — champs de repli mockés (lignes 54-78), notamment dateInscription
Certains champs du profil (dont dateInscription) tombent sur des valeurs par défaut codées en dur si l'API ne les renvoie pas, plutôt que d'afficher un état "non renseigné" explicite.
✓
Présences, cours, résultats, ressources — déjà branchés
Ces onglets utilisent bien GET /api/apprenants/mon-espace, pas de mock résiduel identifié.
✓
Paiement — nettoyé lors d'une passe précédente
Le statut de paiement et le header ont déjà été corrigés dans une session antérieure pour retirer les données mockées identifiées à l'époque.

Fonctionnalités notables propres à chaque côté

🟢 Propre à dash
  • Boutique intégrée (onglet dédié).
  • Suivi de paiement apprenant (onglet Paiement).
  • Dépôt de témoignage.
  • Certifications, Objectifs, Examens comme onglets séparés (plus granulaire côté coaching).
🟣 Propre à bet-elearning
  • Gamification complète : Badges, Mini-jeux, Classement.
  • Dictionnaire intégré.
  • Exercices & devoirs comme onglet dédié (dash n'a pas d'équivalent direct).
  • Progression comme onglet dédié agrégeant plusieurs signaux (dash disperse ça entre Résultats/Examens).
