Journal de déploiement — réalisé

purepro-group.com, en production sur Hostinger

Trace de ce qui a été fait, dans l'ordre, pour faire tourner le Frontend et dash sur un VPS Hostinger unique — y compris les incidents rencontrés en cours de route et comment ils ont été résolus. bet-elearning n'a volontairement pas été déployé cette fois.

Frontend — purepro-group.com dash — dash.purepro-group.com Backend — api.purepro-group.com bet-elearning — non déployé (reporté)

Ce qui a été fait, dans l'ordre

1

Achat domaine + VPS

purepro-group.com et un VPS KVM 1 (1 vCPU, 4 Go RAM) chez Hostinger, OS installé en Plain OS → Ubuntu 24.04 LTS.

2

Connexion SSH

Le premier essai en ligne de commande locale a échoué (mot de passe root altéré lors d'un copier-coller depuis un fichier de notes de l'éditeur). Résolu en utilisant le terminal navigateur intégré de hPanel, qui contourne tout problème de terminal local.

3

Installation système

curl ... setup_20.x | bash puis apt install nodejs git nginx — Node v20.20.2 installé.

4

Clone du repo — dépôt privé

git clone en HTTPS a échoué (GitHub n'accepte plus les mots de passe de compte, et le repo est privé). Contourné en rendant le repo temporairement public le temps du clone, puis remis en privé juste après.

5

Backend en production

.env recréé sur le VPS avec les vraies valeurs, lancé via pm2 start src/server.js --name bet-backend, pm2 save + pm2 startup pour la résilience au reboot.

6

Build dash — mémoire insuffisante

JavaScript heap out of memory pendant npm run build (4 Go de RAM ne suffisaient pas pour ce build webpack, avec le Backend déjà actif en parallèle). Résolu en ajoutant 4 Go de swap : fallocate + mkswap + swapon + entrée /etc/fstab.

7

Dépendances manquantes dans dash

Le build a révélé deux trous entre le code et package.json (invisibles en local car node_modules y était déjà rempli manuellement) :

react-toastify — importé dans 6 fichiers sans jamais être déclaré. Remplacé partout par react-hot-toast (déjà la vraie librairie de toasts de l'app) ; 3 des 6 fichiers (AuthRoute.js, RegisterMiddleware.js, AuthMiddleware.js) se sont avérés être du code mort jamais importé nulle part — supprimés.

redux — le store était branché à la racine (index.js) mais aucun composant n'utilisait useSelector/useDispatch. Scaffolding entièrement supprimé (src/Redux/, react-redux).

8

git pull bloqué par package-lock.json local

Chaque npm install exécuté sur le VPS régénérait légèrement package-lock.json, ce qui bloquait les git pull suivants ("local changes would be overwritten"). Résolu avec git checkout -- package-lock.json avant chaque pull.

9

Nginx — 3 blocs serveur

Un fichier par sous-domaine dans /etc/nginx/sites-available/ (frontend, dash, api), activés via des liens symboliques dans sites-enabled/.

10

DNS + SSL

3 enregistrements A (@, dash, api) vers 191.215.41.58 chez Hostinger. Certificat Let's Encrypt obtenu en une commande pour les 4 domaines (certbot --nginx -d purepro-group.com -d www... -d dash... -d api...) — déployé automatiquement dans les 3 blocs Nginx.

11

Rebuild avec les vraies URLs

Frontend/.env.production et dash/.env.production mis à jour (REACT_APP_API_URL=https://api.purepro-group.com, à la place de l'ancien backend Vercel), rebuild sur le VPS. Backend/.env mis à jour avec FRONTEND_URL, DASHBOARD_URL, BACKEND_URL et ALLOWED_ORIGINS réels, puis pm2 restart bet-backend.
