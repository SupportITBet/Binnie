03Étapes d'implémentation proposées

Récupérer la clé API dans le compte Brevo
SMTP & API → Clé API. L'ajouter à Backend/.env (local) et Backend/.env du VPS (prod) comme BREVO_API_KEY — emailService.js bascule automatiquement dessus, aucun code à changer pour l'email.
Décider du canal SMS : Brevo SMS ou autre
Brevo propose un vrai produit SMS Transactionnel, mais il faut déclarer un expéditeur (nom court validé) et il facture par SMS séparément de l'email — à confirmer que c'est bien le choix voulu avant de coder, plutôt qu'un fournisseur SMS local ivoirien parfois plus simple à faire approuver.
Créer smsService.js (même forme que emailService.js)
Une fonction envoyerSms({ to, message }) appelant l'API SMS de Brevo — même structure que brevoSend(), pour rester cohérent avec le reste du code.
Brancher dans jobsPaiements.js
À chaque rappel J-7/J-3/J-1 déjà envoyé en in-app, vérifier plan.canal_email/plan.canal_sms et appeler emailService/smsService en plus — les cases cochées deviennent enfin actives, sans changement pour l'utilisateur final côté dashboard.
Réutiliser pour les badges de fidélité
Le futur job mensuel (proposition précédente) branche directement sur les mêmes deux services — aucune nouvelle intégration à faire, juste un nouvel appelant.
⚠️ WhatsApp via Brevo (Business API) est un produit à part, nécessitant une validation Meta/WhatsApp Business séparée — nettement plus lourd que l'email/SMS. À traiter comme une phase 3 distincte, pas dans ce chantier.

En une phrase

L'email fonctionne déjà réellement via Brevo — il ne manque qu'une clé API pour passer du SMTP à l'API. Le SMS est entièrement à construire (mais sur le même modèle que l'email existant). Les deux se branchent ensuite sur les jobs déjà en place (paiements) et à venir (badges), sans toucher aux dashboards.
