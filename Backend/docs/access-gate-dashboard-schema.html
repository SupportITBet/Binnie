BET · Sécurité — dash (staff)

Connexion staff déplacée hors de "/"

Le chemin racine du dashboard interne (dash.purepro-group.com/) affichait directement la page de connexion admin — n'importe qui tapant l'URL savait immédiatement qu'un espace staff existait là, et pouvait tenter de s'y connecter. La connexion vit maintenant sur un chemin dédié, non deviné.

✅
Fait — aucune interruption pour le staff déjà connecté. Seul le point d'entrée change. Tous les rôles, permissions et tokens (admin_token) restent identiques — ce chantier ne touche qu'aux chemins de redirection vers/depuis la connexion.

Avant / après

✗ Avant
dash.purepro-group.com/

Affichait directement <LoginAdmin /> — la page de connexion staff, visible par n'importe quel visiteur.

→
✓ Après
dash.purepro-group.com/bet-staff-access

"/" n'est plus déclarée comme route — elle tombe sur le path="*" déjà en place et affiche NotFoundPage (404), exactement comme n'importe quelle URL inexistante.

Ce qui a été modifié

Chaque endroit qui redirigeait vers "/" en tant que page de connexion staff a été mis à jour vers /bet-staff-access — sans quoi la déconnexion ou une session expirée auraient renvoyé vers un 404 au lieu de l'écran de connexion.

Parcours d'accès, étape par étape

1
Un membre du staff ouvre /bet-staff-access
Seul ce chemin précis affiche LoginAdmin. Il doit être connu/communiqué directement (favori, lien interne) — plus jamais deviné en tapant juste le domaine.
2
Connexion réussie → redirection vers son propre dashboard
Logique inchangée : DASHBOARD_PAR_ROLE route chaque rôle (onboarding, commercial, PA advisor…) vers sa page dédiée, protégée par PrivateAdminRoute.
3
Déconnexion, session expirée, ou accès sans token
Dans les 3 cas, la redirection pointe maintenant vers /bet-staff-access — jamais vers "/".
4
Un visiteur quelconque ouvre le domaine racine
Tombe sur NotFoundPage (404) — aucune indication qu'un espace staff existe à cette adresse.

Portail à code sur "/" — implémenté

✅
"/" demande maintenant un code d'accès partagé avant d'atteindre /bet-staff-access. Page neutre (AccessGate.jsx) : un simple champ, aucune indication qu'il s'agit d'un espace staff. Code correct → redirection vers /bet-staff-access. Code incorrect/absent → le champ se vide, la page reste neutre, sans message d'erreur.

Vérification côté Backend — le code n'est jamais visible dans le bundle JS : POST /api/access-gate/verify (public, protégé par authLimiter anti brute-force) compare le code saisi à un hash bcrypt stocké dans la table Supabase access_gate_config.

Modulable par le Super Admin — nouvel onglet 🔑 Code d'accès dans SuperAdminDashboard (Configuration de la plateforme) pour changer le code à tout moment, sans toucher au code source. PUT /api/access-gate est protégé par requireSuperAdmin — aucun autre rôle ne peut le modifier.

Fichiers : Backend/sql/access_gate_config_migration.sql, Backend/src/routes/accessGate.js, dash/src/Pages/AccessGate.jsx, dash/src/Pages/NotFoundPage.jsx (404 modernisée, utilisée pour toute autre route inconnue).
