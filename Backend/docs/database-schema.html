BET · Architecture

Schéma complet de la base de données

Toutes les tables Supabase de la plateforme BET, regroupées par domaine métier, avec leurs relations (clés étrangères) entre elles. Généré le 20 août 2026.

Méthode et limites. Ce schéma est reconstruit à partir des fichiers Backend/sql/par_table/*.sql (dump consolidé de chaque table, historique de migrations inclus) — pas d'une lecture directe du catalogue Postgres en production (aucun accès SQL direct disponible dans cet environnement). Certaines relations indiquées en pointillés sont utilisées comme telles dans le code (Backend/src/routes) mais ne sont pas déclarées comme contrainte FK en base — par exemple notifications.user_id, paiements_parcours.commercial_id, ou les colonnes de paiements_touchpoint ajoutées après coup. À vérifier ponctuellement si une précision absolue est nécessaire pour une migration ou un audit RLS.

01 — Cœur métier

Parcours, Paiements & Utilisateurs

Le pipeline central : un prospect est capté (formulaire en ligne, test de niveau, devis B2B), assigné à une assistante/commerciale, éventuellement rattaché à un centre, puis paie via TouchPoint ou manuellement. Chapeauté par utilisateurs (comptes internes : commerciales, PA, onboarding, superviseurs…).
